# DESIGN.md — 책어디 (WhereBook)

UI를 만들거나 고칠 때 이 문서를 따른다. 값(색·크기)의 원본은 `globals.css`(tokens.css)이고, 이 문서는 **규칙과 판단 기준**을 정한다. 이 문서에 hex 값을 새로 적지 말고 CSS 변수 이름으로만 말한다.

규칙의 우선순위: **접근성·사용성 기본 규칙 > 책어디 규칙 > 개별 화면의 취향.** 충돌하면 위가 이긴다.

---

## 1. 서비스가 하는 일

책어디는 "빌리고 싶은 책을 어느 도서관에서, 어떤 순서로 빌릴지" 알려주는 서비스다. 모든 화면은 세 질문 중 하나에 답한다.

| 영역 | 질문 | 핵심 화면 |
|---|---|---|
| 검색 | 어떤 책? | 메인, 검색 결과, 책 상세 |
| 내 주변 | 어디서? | 지도 + 도서관 목록 |
| 대출가방 | 어떻게 빌리지? | 가방 목록, 동선 추천 |

화면에 요소를 추가할 때는 "이게 이 화면의 질문에 답하는 데 필요한가"를 먼저 묻는다. 아니면 넣지 않는다.

---

## 2. 기본 원칙

1. **화면당 주요 행동은 하나.** 브랜드 색으로 채운 버튼(primary)은 한 화면에 하나만 둔다. 나머지는 연한 배경(subtle) 또는 텍스트 버튼.
2. **색은 아껴 쓴다.** `--brand`는 행동(버튼, 링크), 위치(핀), 선택 상태에만 쓴다. 장식용으로 쓰지 않는다.
3. **정보는 색만으로 전달하지 않는다.** 상태는 색 + 모양(아이콘, 채움/테두리) + 텍스트 중 최소 두 가지로 구분한다.
4. **여백으로 묶고, 선은 최소로.** 그룹은 간격으로 먼저 구분하고, 그래도 부족할 때만 구분선이나 테두리를 쓴다.
5. **같은 것은 같은 이름으로.** 버튼 문구와 결과 메시지는 같은 동사를 쓴다 ("담기" → "담김", "동선 짜기" → 동선 결과).

## 3. 색

변수 정의는 `globals.css` 참고. 컴포넌트에서 hex 값을 직접 쓰지 않는다.

| 역할 | 변수 | 쓰는 곳 |
|---|---|---|
| 브랜드 | `--brand`, `--brand-hover`, `--on-brand` | 주요 버튼, 링크, 대출 가능 핀, 활성 탭, 배지 |
| 브랜드 연한 면 | `--brand-subtle` | 담김 상태, 대출 가능 배지, 선택된 행·카드, 보조 버튼 |
| 배경 | `--bg` | 앱 전체 배경 |
| 면 | `--surface` | 검색창, 칩, 세그먼트 컨트롤 바탕 |
| 테두리 | `--border`, `--border-strong` | 카드, 구분선 / 외곽선 버튼 |
| 글자 | `--text` > `--text-2` > `--text-3` > `--text-muted` | 제목·본문 > 강조 본문 > 비활성 컨트롤 > 캡션·메타 |
| 경고 | `--warning` | 오늘 휴관, 반경 안 전부 대출중 |

### 명암비 (WCAG 2.2 AA)
- 본문 크기 글자: 배경 대비 **4.5:1 이상**
- 18px 이상 굵은 글자, 아이콘, 입력창 테두리 등 UI 요소: **3:1 이상**
- 새 색 조합을 만들면 라이트·다크 둘 다 확인한다. 현재 토큰 조합은 모두 기준을 통과한다.
- `--control-muted`, `--icon-muted`는 아이콘·장식 전용이다. 읽어야 하는 글자에 쓰지 않는다.

### 다크 모드
- 같은 변수 이름에 값만 바뀐다. 컴포넌트에 다크 전용 분기를 쓰지 않는다.
- 우선순위: 설정에서 고른 값(`data-theme`) > 시스템 설정.
- 이미지·지도 타일처럼 변수로 못 바꾸는 요소는 다크에서 밝기를 따로 확인한다.

## 4. 글자

- 글꼴: `--font-sans` (IBM Plex Sans KR) 하나만 쓴다. 굵기로 위계를 만든다.
- 본문 최소 크기 **16px**(`--text-base`). 모바일에서 16px 미만 입력창은 iOS가 자동 확대하므로 입력창은 반드시 16px 이상.
- 보조 정보는 13px(`--text-sm`)까지만 내린다. 12px(`--text-xs`)은 탭 라벨·배지 전용.
- 줄간격: 본문 `--leading-normal`(1.5), 큰 제목 `--leading-tight`(1.3).
- 제목은 `--tracking-title`로 살짝 좁힌다. 본문은 기본 자간.
- 한 줄 길이는 웹에서 한글 기준 **40자 안팎**을 넘기지 않는다 (긴 설명 문단은 최대 폭 제한).
- 단위는 `rem`. 사용자가 브라우저 글자 크기를 키워도 레이아웃이 깨지지 않아야 한다 (200% 확대 확인).

| 용도 | 크기 | 굵기 |
|---|---|---|
| 웹 메인 카피 | `--text-3xl` | bold |
| 모바일 메인 카피 | `--text-2xl` | bold |
| 화면 제목 | `--text-xl` | bold |
| 섹션 제목 | `--text-lg` | bold |
| 목록 항목 제목 | `--text-base` | semibold |
| 버튼·칩 | `--text-md` | semibold (주요) / medium |
| 메타 정보 | `--text-sm` | regular |

## 5. 간격과 레이아웃

- 간격은 **4px 단위**(4, 8, 12, 16, 20, 24, 32, 40, 48, 64)만 쓴다.
- 모바일 좌우 여백 **20px**, 웹 본문 최대 폭 `--content-max`(1120px) 가운데 정렬.
- 관련 있는 요소끼리는 가깝게(8~12px), 섹션 사이는 넓게(24~32px).

### 브레이크포인트

| 범위 | 레이아웃 |
|---|---|
| ~767px | 모바일: 하단 탭 3개, 지도 화면은 바텀시트 |
| 768~1023px | 태블릿: 하단 탭 유지, 본문 폭 제한 |
| 1024px~ | 웹: 상단 헤더 내비게이션, 지도 화면은 왼쪽 패널(`--panel-w`) + 오른쪽 지도 |

**모바일의 아래쪽(바텀시트) = 웹의 왼쪽(패널).** 같은 컴포넌트를 쓰고 배치만 바꾼다. 웹이라고 기능을 더하지 않는다.

### Safe area
- 하단 탭·고정 버튼은 `env(safe-area-inset-bottom)`만큼 아래 여백을 더한다.
- 뷰포트 메타에 `viewport-fit=cover`.

## 6. 상호작용

### 터치·클릭 영역
- 누를 수 있는 모든 요소는 **최소 44×44px** (`--touch`). 아이콘이 작아도 영역은 44px.
- 누를 수 있는 요소 사이 간격 최소 8px.
- 예외: 지도 핀은 36px까지 허용하되, 겹치면 클러스터로 묶는다.

### 상태
모든 인터랙티브 요소는 다섯 상태를 정의한다: 기본, 호버(웹), 눌림, 포커스, 비활성.
- **포커스**: 키보드 포커스는 항상 보여야 한다 (`:focus-visible` 2px 브랜드 외곽선). `outline: none`만 쓰고 대체 스타일을 안 주는 것은 금지.
- **비활성**: 왜 안 되는지 근처에 짧게 알려준다. 가능하면 비활성 대신 누르면 이유를 안내한다.
- **선택됨/눌림 토글**: `aria-pressed` 또는 `aria-current`로 상태를 함께 표시한다.

### 키보드
- Tab 순서는 화면에 보이는 순서와 같다.
- 모달·바텀시트가 열리면 포커스가 안으로 들어가고, Esc로 닫히고, 닫히면 연 버튼으로 돌아간다.
- 지도에서 하는 모든 일(도서관 선택 등)은 옆 목록에서도 할 수 있어야 한다. 지도만으로 접근 가능한 기능은 만들지 않는다.

### 모션
- 사용자의 행동에 반응하는 모션만 쓴다 (시트 열림, 담기 확인). 화면 진입 애니메이션 남발 금지.
- 지속 시간 150~250ms, `ease-out`.
- `prefers-reduced-motion`을 존중한다.

## 7. 화면 상태

데이터를 불러오는 모든 화면은 네 상태를 설계한다.

| 상태 | 규칙 |
|---|---|
| **로딩** | 300ms 이상 걸리면 스켈레톤(실제 레이아웃 모양). 화면 전체 스피너 금지. 대출 가능 여부처럼 늦게 오는 정보는 해당 자리만 스켈레톤. |
| **빈 상태** | 다음 행동을 안내한다. 예: 대출가방이 비면 "읽고 싶은 책을 검색해서 담아보세요" + 검색으로 가는 버튼. |
| **오류** | 무슨 일이 생겼는지 + 어떻게 하면 되는지. 사과하지 않고 모호하게 쓰지 않는다. 예: "도서관 정보를 불러오지 못했어요. 다시 시도" |
| **일부 실패** | 일부 도서관 조회가 실패해도 나머지는 보여주고, 실패한 항목만 표시한다. |

레이아웃이 데이터 도착 후 밀리지 않게 이미지·표지·지도 영역은 크기를 미리 잡는다 (CLS 0.1 미만).

## 8. 컴포넌트 규칙

### 버튼
| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| Primary | `--brand` 채움 + `--on-brand` 글자, 높이 48~56px | 화면의 주요 행동 하나 (검색, 동선 짜기, 대출가방에 담기) |
| Secondary | `--brand-subtle` 채움 + `--brand` 글자 | 보조 행동 (지도에서 보기, 내 위치로 찾기) |
| Text | 배경 없음 | 더보기, 전체 삭제, 정렬 |
| Icon | 44px 영역, `aria-label` 필수 | 닫기, 설정, 확대 |

- 버튼 문구는 동사로 끝난다: "검색", "담기", "동선 짜기", "길찾기". "확인", "제출" 같은 모호한 말을 쓰지 않는다.
- 아이콘만 있는 버튼은 반드시 `aria-label`.

### 입력창
- 화면에 라벨이 안 보여도 `<label>`은 반드시 있다 (`.sr-only`).
- placeholder는 예시이지 라벨이 아니다.
- 검색창은 `type="search"`, `<form method="get">`으로 JS 없이도 동작하게 한다.
- 지우기(✕) 버튼은 값이 있을 때만 보인다.

### 대출 상태 표시 (책어디 핵심)
대출 상태는 앱 전체에서 같은 모양을 쓴다.

| 상태 | 핀 | 배지 | 목록 문구 |
|---|---|---|---|
| 대출 가능 | `--brand` 채움 + 체크 아이콘 | `--brand-subtle` 바탕 "대출 가능" | "반경 안 N곳에서 대출 가능" |
| 대출중 | `--bg` 바탕 + 회색 테두리 + "대출중" 글자 | `--surface` 바탕 "대출중" | — |
| 미소장 / 반경 밖 | 작은 회색 점 (기본 숨김 가능) | 표시 안 함 | — |
| 전부 대출중 | — | — | `--warning` + 경고 아이콘 "반경 안 모든 도서관 대출중" |

도서관 운영 상태도 같은 원칙: 운영 중은 채운 점 + "운영 중 · N시까지", 휴관은 빈 원 + `--warning` "오늘 휴관".

### 목록 행
- 높이 최소 56px, 한 행 전체가 하나의 링크. 행 안의 보조 버튼(담기, 삭제)은 링크 밖에 둔다 (링크 안에 버튼 중첩 금지).
- 왼쪽에 대상(표지·이름), 오른쪽에 상태나 행동 하나.

### 하단 탭 (모바일)
- 3개 고정: 검색 / 대출가방 / 내 주변. 대출가방이 가운데.
- 아이콘 + 라벨 항상 같이. 활성 탭은 색 + 굵기 + `aria-current="page"`.
- 대출가방 배지는 담은 권수. 0이면 숨긴다.
- 상세·검색 입력·동선 결과처럼 깊은 화면에선 탭을 숨기고 뒤로가기를 쓴다.

### 지도
- 지도 위 떠 있는 요소(검색바, 필터, 버튼)는 `--bg` 바탕 + `--shadow-float`.
- 반경 필터는 4단계 세그먼트(1·3·5·10km). 선택한 반경은 지도에 원으로 그린다.
- 기준점(내 위치 / 지도 중심 / 직접 고른 지역)은 항상 글자로 보여준다 ("서울 마포구 기준 3km").
- 지도를 움직이면 "이 지역에서 다시 검색" 버튼을 띄운다. 자동 재검색하지 않는다.
- 목록과 지도는 선택 상태를 공유한다: 목록에서 고르면 핀이 커지고, 핀을 누르면 목록 행이 강조된다.

### 바텀시트 / 패널
- 모바일 바텀시트는 손잡이(핸들) + 요약 제목 + 목록. 세 높이(요약 / 절반 / 전체).
- 웹에선 같은 내용이 왼쪽 패널로 고정된다.

### 모달
- 설정, 확인 대화상자에만 쓴다. 정보를 보여주는 용도로 쓰지 않는다.
- 배경을 누르거나 Esc로 닫힌다. 되돌릴 수 없는 행동(가방 전체 삭제)만 확인을 받는다.

## 9. 문구

- 해요체, 짧고 구체적으로. "~하세요"보다 "~해요/~할 수 있어요".
- 사용자 입장의 말로: "소장 정보 API 오류" ✕ → "대출 정보를 불러오지 못했어요" ○
- 숫자는 단위와 함께: "0.6km", "도보 9분", "3권".
- 한 화면에서 같은 대상은 같은 이름: "대출가방"을 "가방", "장바구니"로 섞어 쓰지 않는다.
- 중간점(·)은 메타 정보 구분에만 쓴다 ("한강 · 창비 · 2014").

### 다국어
- 지금은 한국어로 먼저 만들고, 영어 전환에 대비해 공간을 확보해둔다 (상세 규칙은 CLAUDE.md).
- 영어는 한국어보다 30~50% 길다. 버튼·탭·배지는 영어 기준으로 넘침을 확인하고, 줄바꿈 대신 말줄임이 필요한 곳을 미리 정한다. 문구가 들어가는 요소에 고정 폭을 주지 않는다.
- 책 제목·저자·도서관 이름은 번역하지 않는다 (데이터 원문 그대로).
- `<html lang>`은 현재 언어로 바꾼다.

## 10. 시맨틱 마크업과 SEO

- 화면마다 `<h1>`은 하나. 제목 단계(h1 → h2 → h3)를 건너뛰지 않는다.
- 랜드마크: `<header>`, `<nav aria-label>`, `<main>`, `<aside>`.
- 이동은 `<a href>`, 동작은 `<button>`. `div`에 onClick 금지.
- 색인 대상: `/book/[isbn]`, `/library/[libCode]`, 지역별 도서관 목록. SSR로 핵심 내용(제목, 저자, 소장 도서관)이 HTML에 들어 있어야 한다.
- 검색 결과(`/search?q=`)는 `noindex`.
- 책 표지 이미지는 `alt`에 "책 제목 표지". 장식 아이콘은 `aria-hidden="true"`.

## 11. 성능 체감

- 첫 화면에 필요한 것만 먼저: 검색창은 즉시, 인기 도서·주변 도서관은 뒤에 와도 된다.
- 표지 이미지는 지연 로딩 + 고정 비율(5:7) 자리 확보.
- 대출 가능 여부처럼 느린 외부 API 결과는 화면을 막지 않는다. 먼저 목록을 보여주고 상태만 나중에 채운다.
- 폰트는 `next/font`로 자체 호스팅, 필요한 굵기(400·500·600·700)만.

## 12. 새 화면을 만들 때 체크리스트

- [ ] 이 화면은 세 질문(어떤 책? / 어디서? / 어떻게?) 중 무엇에 답하는가
- [ ] Primary 버튼이 하나뿐인가
- [ ] 색은 CSS 변수만 썼는가, 라이트·다크 둘 다 확인했는가
- [ ] 누를 수 있는 것은 전부 44px 이상인가
- [ ] 상태를 색 말고 다른 방법으로도 구분하는가
- [ ] 로딩·빈 상태·오류 상태를 설계했는가
- [ ] 키보드만으로 쓸 수 있는가, 포커스가 보이는가
- [ ] 영어로 바꿔도 넘치지 않는가
- [ ] 모바일(바텀시트)과 웹(왼쪽 패널) 배치가 둘 다 정의됐는가
