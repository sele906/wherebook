# 책어디 (WhereBook) — web

도서관에서 빌리고 싶은 책을 어디서, 어떤 순서로 빌릴지 알려주는 서비스의 프론트엔드.
백엔드는 같은 레포의 `/api`(Spring Boot, Render 배포)이고, 이 폴더는 Next.js App Router(Vercel 배포)다.
**이 폴더 밖(`/api`)은 수정하지 않는다.** 백엔드 변경이 필요하면 무엇이 필요한지 말로 알려준다.

## 기술 규칙

- 언어는 JavaScript(`.jsx`, `.js`). TypeScript로 바꾸지 않는다.
- 새 패키지를 설치하기 전에 먼저 이유와 대안을 말하고 확인받는다.
- 환경 변수: 백엔드 주소는 `<!-- 변수명 적기 -->`. 브라우저에 노출되는 `NEXT_PUBLIC_` 변수에 비밀 값을 넣지 않는다.

## 렌더링 원칙 (SEO·AI 크롤러가 핵심 목표)

- 기본은 **Server Component**. `'use client'`는 상호작용이 꼭 필요한 가장 작은 컴포넌트에만 붙인다.
- 아래 페이지는 핵심 내용이 **서버에서 렌더링된 HTML에 들어 있어야** 한다. 작업 후 페이지 소스 보기로 확인한다.
  - `/book/[isbn]` — 책 제목, 저자, 소장 도서관
  - `/libraries/[libCode]` — 도서관 이름, 주소, 운영 정보
  - 지역별 도서관 목록
- 위 페이지는 `generateMetadata`로 제목·설명을 페이지마다 만든다. `<h1>`은 페이지당 하나.
- `/search?q=` 검색 결과는 `noindex`.
- 지도는 클라이언트 전용이다. 지도 SDK는 dynamic import(`ssr: false`)로 불러오고, 지도가 없어도 목록만으로 모든 기능을 쓸 수 있어야 한다.

## 데이터

- 데이터는 **우리 백엔드 API만** 호출한다. 도서관정보나루 API를 프론트에서 직접 부르지 않는다 (API 키 노출, 일일 호출 한도).
- API 호출은 `lib/api`(또는 정해진 한 곳)에 모으고, 컴포넌트에서 `fetch`를 직접 쓰지 않는다.
- 책의 식별자는 항상 **ISBN13**. 제목으로 책을 넘기지 않는다 (동명 도서·개정판).
- 대출 가능 여부는 느리고 비싸다. 목록 화면에서 책마다 조회하지 않고, 책 상세·지도·동선 화면에서만 조회한다. 결과가 늦게 와도 화면을 막지 않는다.
- 목록과 지도 보기는 같은 API 응답을 공유한다. 보기를 바꿀 때 다시 호출하지 않는다.

## 기능별 규칙

- **빌릴 책**: 빌리러 갈 책 목록이다(대출은 도서관에서 하고, 앱은 대출하지 않는다). 이름은 층마다 같은 뿌리를 쓴다: 화면 "빌릴 책" / 주소 `/borrow-list` / API `/api/borrow-list` / 테이블 `borrow_list_item`. 백엔드 API를 통해 DB에 저장한다. 프론트에 따로 원본을 두지 않고(`localStorage`에 빌릴 책 데이터 저장 금지), 화면 상태는 API 응답을 기준으로 맞춘다. 추가·빼기는 바로 화면에 반영하되(낙관적 업데이트) 실패하면 되돌리고 알려준다. 최대 권수 제한이 있다(API 호출량 보호).
- **대출 한도**: 도서관당 대출 권수 한도(기본 14권)를 동선 계산과 빌릴 책 UI에 반영한다.
- **기준 위치**: 현재 위치 / 직접 고른 지역 / 지도 중심 중 지금 무엇이 기준인지 항상 화면에 글자로 보여준다. 위치 권한이 없거나 해외면 지역 선택으로 안내한다.
- **기준 위치 저장 (GPS 좌표는 서버로 보내지 않는다)**: 사용자가 고른 기준(activeLocation)은 쿠키에 저장하고 서버에서 읽는다. 쿠키는 요청마다 서버로 가므로 넣는 값을 기준 종류에 따라 나눈다.
  - 주소·지역 기준: 쿠키에 좌표까지 넣는다 → 서버가 그 좌표로 거리 계산·정렬까지 해서 렌더링.
  - GPS(현재 위치) 기준: 쿠키에는 `{ source: "gps" }`만 넣고 좌표는 넣지 않는다 → 서버는 위치 없이 렌더링하고, 측위한 좌표로 하는 거리 계산은 클라이언트에서 한다.
  - GPS 좌표를 쿠키·URL·서버 로그 등 서버로 가는 경로에 싣지 않는다.
  - 기준 위치의 원본은 localStorage(`lib/locationStore.js`, `wherebook:` 접두어 키). GPS는 `{ type: "gps" }`만 저장하고 좌표는 매번 측정해 React state에만 둔다. 저장한 위치는 id로만 가리킨다. 쿠키는 SSR에 거리순이 필요해질 때 추가한다.

## 다국어 (ko / en)

지금은 언어 파일 없이 **한국어 문구를 컴포넌트에 직접 쓴다.** 대신 나중에 영어로 옮길 때 다시 짜지 않도록 아래를 지킨다.

- **공간 확보**: 영어는 한국어보다 30~50% 길다고 보고 레이아웃을 잡는다. 문구가 들어가는 요소(버튼, 탭, 배지, 칩, 제목)에 고정 `width`를 주지 않고, 늘어나도 깨지지 않게 `min-width`·줄바꿈·말줄임(`text-overflow: ellipsis`) 중 무엇을 쓸지 정해둔다. 하단 탭 라벨처럼 공간이 좁은 곳은 영어 예상 문구(예: "To borrow", "Nearby")로 넘침을 확인한다.
- **문장 쪼개기 금지**: 문장을 조각으로 이어 붙이지 않는다. `"반경 " + n + "km 안에 " + count + "곳"` ✕ → 숫자를 넣을 자리가 있는 한 문장으로 쓴다. 영어는 어순이 달라서 조각 이어 붙이기는 번역이 안 된다.
- **문구를 이미지·SVG에 넣지 않는다.** 글자는 항상 텍스트로.
- **날짜·숫자·거리**는 `Intl.DateTimeFormat`, `Intl.NumberFormat`처럼 언어에 따라 바뀌는 방식으로 표시한다.
- 책 제목, 저자, 도서관 이름은 번역 대상이 아니다 (데이터 원문 그대로).
- `<html lang="ko">`를 지금부터 넣어둔다.

## 테마 (라이트 / 다크)

- `<html data-theme="light|dark">`로 전환하고, 값이 없으면 시스템 설정을 따른다.
- 첫 화면이 깜빡이지 않도록 저장된 테마는 하이드레이션 전에 적용한다.
- 컴포넌트에 다크 전용 분기를 만들지 않는다. CSS 변수 값만 바뀐다.

## UI 작업 규칙

- UI를 만들거나 고칠 때는 @DESIGN.md 를 따른다.
- 색·크기는 직접 쓰지 말고 `globals.css`의 CSS 변수만 쓴다.
- 새 화면이나 컴포넌트를 만들면 DESIGN.md 맨 아래 체크리스트로 스스로 검토하고, 통과 못 한 항목을 알려준다.

## 작업 방식

- 큰 작업은 시작 전에 단계별 계획을 먼저 보여주고, 한 단계씩 진행한다.
- 변경은 작게 나눈다. 요청과 관계없는 파일은 고치지 않는다.
- 끝나면 바꾼 파일과 이유를 짧게 정리하고, 직접 확인할 방법(어떤 URL에서 무엇을 보면 되는지)을 알려준다.
